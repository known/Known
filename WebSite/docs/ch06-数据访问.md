# 第6章 数据访问

Known 的数据访问层围绕 `Known/Data/Database*.cs` 展开。它不是 EF Core 风格的 DbContext，而是一套更轻、更贴近业务后台开发的统一数据访问模型。

---

## 6.1 核心对象

### 6.1.1 `Database`

`Database` 是数据访问主入口，支持：

- 普通查询
- 分页查询
- 条件表达式查询
- 插入、更新、删除
- 事务
- 存储过程
- Schema 操作
- 多数据库适配

它通过多个分部文件组织能力：

- `Database.cs`
- `Database.Query.cs`
- `Database.Execute.cs`
- `Database.Page.cs`
- `Database.Trans.cs`
- `Database.SP.cs`
- `Database.Schema.cs`
- `Database.Table.cs`

### 6.1.2 `DbProvider`

`DbProvider` 是各数据库的实际适配器，仓库中已实现：

- SQLite
- SQL Server
- MySQL
- PostgreSQL
- Oracle
- 达梦
- Access

### 6.1.3 `QueryBuilder<T>`

Known 支持将表达式树转换为查询条件，因此很多查询可以写成类似 LINQ 的风格，而不是手写 SQL 字符串。

---

## 6.2 配置数据库

在宿主启动时，通过 `AppInfo.Database` 配置数据库：

```csharp
option.App.Database = db =>
{
    db.AddSQLite<Microsoft.Data.Sqlite.SqliteFactory>(connString);
    db.AddMySql<MySqlConnector.MySqlConnectorFactory>();
};
```

之后 `AddKnownCore` 或 `UseKnown` 会接管数据库初始化、表迁移和语言/模块基础数据加载。

---

## 6.3 获取 `Database` 实例

在服务层中通常直接通过 `ServiceBase.Database` 访问数据库：

```csharp
class ProduceService(Context context) : ServiceBase(context)
{
    public async Task<TbMaterial> GetMaterialAsync(string id)
    {
        var info = await Database.QueryByIdAsync<TbMaterial>(id);
        info ??= new TbMaterial();
        return info;
    }
}
```

`ServiceBase` 会自动把当前用户放入 `db.User`，因此数据库操作天然感知当前登录上下文。

---

## 6.4 常见查询方式

### 6.4.1 查询全部或条件列表

```csharp
var list = await Database.Query<TbMaterial>()
                         .Where(x => x.CustGNo.Contains(keyword))
                         .OrderBy(x => x.CustGNo)
                         .ToListAsync();
```

### 6.4.2 单条查询

```csharp
var model = await Database.QueryAsync<TbMaterial>(x => x.Id == id);
```

### 6.4.3 按主键查询

```csharp
var model = await Database.QueryByIdAsync<TbMaterial>(id);
```

### 6.4.4 原始条件查询

当表达式无法满足复杂需求时，也可以使用 SQL 片段或参数对象进行查询。

---

## 6.5 分页查询

分页是后台系统最常见的查询形式。Known 提供 `PagingCriteria` 与 `PagingResult<T>` 两个核心对象。

常见写法：

```csharp
public Task<PagingResult<TbMaterial>> QueryMaterialsAsync(PagingCriteria criteria)
{
    return Database.QueryPageAsync<TbMaterial>(criteria);
}
```

`PagingCriteria` 一般承载：

- 页码
- 页大小
- 查询条件
- 排序信息
- 导出模式

这套模型被页面基类、导出能力和服务接口共同复用。

---

## 6.6 保存数据

### 6.6.1 通用保存

```csharp
await Database.SaveAsync(model);
```

`SaveAsync` 会根据实体状态判断是插入还是更新，并处理通用字段。

### 6.6.2 批量插入

```csharp
await Database.InsertListAsync(list);
```

### 6.6.3 删除

```csharp
await Database.DeleteAsync<TbMaterial>(id);
await Database.DeleteAsync<TbMaterial>(x => x.CustGNo == custGNo);
```

---

## 6.7 事务处理

后台业务开发离不开事务。Known 提供统一事务入口：

```csharp
return await Database.TransactionAsync("保存", async db =>
{
    await db.SaveAsync(head);
    await db.InsertListAsync(details);
});
```

事务能力特别适合以下场景：

- 主从表保存
- 批量导入
- 流程与业务数据同步修改
- 模块导入导出

---

## 6.8 平台模式下的数据隔离

Known 的数据访问并不只是执行 SQL，还会结合用户上下文和平台字段工作。尤其在平台模式下，`CompNo` 常常会作为租户隔离字段参与查询和保存。

这意味着：

1. 业务实体最好继承 `EntityBase`。
2. 租户数据不要绕开框架底层直接写裸 SQL。
3. 平台化项目要明确哪些表是租户表，哪些是系统表。

---

## 6.9 表结构与初始化

在 Web 宿主中，`UseKnown()` 会在检测到数据库配置后执行初始化逻辑，包括：

- 迁移表结构
- 加载语言数据
- 迁移模块数据

这也是为什么首次启动时系统能自动具备基础表和模块数据。

---

## 6.10 数据访问与导入导出的关系

导入、导出、任务、工作流等高级能力底层仍然建立在 `Database` 之上：

- 导入器最终落库靠 `Database`
- 导出列表通常基于分页查询结果
- 任务执行器内部仍然使用数据库
- 工作流服务会保存流程定义、日志、审批状态

因此，掌握 `Database` 基本能力后，很多高级模块的源码会更容易理解。

---

## 6.11 推荐实践

1. 普通业务优先使用表达式查询。
2. 列表页优先返回 `PagingResult<T>`。
3. 跨表操作优先包裹事务。
4. 尽量通过 `ServiceBase.Database` 访问数据，而不是在页面里直接处理复杂 SQL。
5. 平台项目要注意 `CompNo` 和系统表边界。

## 本章小结

Known 的数据访问层特点很明确：

1. 自带轻量 ORM，适合后台业务开发。
2. 支持表达式、分页、事务和多数据库。
3. 与服务模型、页面模型和平台字段深度协同。
4. 是导入导出、任务、工作流等能力的基础支撑。
