# 第10章 插件体系

插件体系是 Known 最有辨识度的能力之一。它不只是“允许引用额外程序集”，而是把页面、导航、开发中心、低代码区块和系统增强模块都统一纳入插件模型。

---

## 10.1 插件体系概览

从源码看，插件核心位于：

- `Known/Plugins/Attributes.cs`
- `Known/Plugins/PluginConfig.cs`
- `Known/Plugins/PluginBase.cs`
- `Known/Plugins/PluginPage.cs`
- `Known/Plugins/PluginService.cs`

插件体系主要解决四类问题：

1. 如何发现插件。
2. 如何分类插件。
3. 如何把插件放进正确的入口位置。
4. 如何为页面区块保存配置和布局。

---

## 10.2 插件分类

Known 支持四类主要插件特性。

### 10.2.1 普通插件 `[Plugin]`

适合通用扩展组件或特殊页面入口。

可配置属性包括：

- `Name`
- `Icon`
- `Category`
- `Sort`
- `Role`
- `Parent`

### 10.2.2 开发中心插件 `[DevPlugin]`

用于把页面挂入开发中心，例如：

- `ModulePage`
- `TenantPage`
- `CodingPage`
- `WebApiPage`

### 10.2.3 顶部导航插件 `[NavPlugin]`

用于出现在系统顶部导航区域，例如字号切换、语言切换、主题切换等导航型组件。

### 10.2.4 页面区块插件 `[PagePlugin]`

用于页面编排和低代码页面区块，例如：

- 表格区块
- 表单区块
- 列表区块
- 图表区块
- 模板区块
- AI 区块

---

## 10.3 页面区块插件类型

`PagePluginType` 枚举定义了页面区块分类：

- `Module`
- `Table`
- `Form`
- `Detail`
- `List`
- `Chart`
- `Template`
- `AI`
- `Other`

这些分类决定了插件在“添加区块”时如何分组展示。

---

## 10.4 插件扫描与注册

插件的注册并不是手工维护列表，而是通过程序集扫描完成。

核心过程如下：

1. 宿主或插件调用 `Config.AddModule(assembly)`。
2. 初始化器扫描程序集中的页面、服务、动作、语言项和插件特性。
3. `PluginConfig.AddPlugin(...)` 根据特性类型将插件加入分类列表。

`PluginConfig` 内部会维护：

- `Plugins`
- `TopNavs`
- `NavPlugins`
- `DevPlugins`
- `PagePlugins`

这套分类结果会直接用于导航渲染和页面区块选择器。

## 10.5 插件运行时模型

### 10.5.1 `PluginInfo`

每个插件在页面中实际落地时，对应一个 `PluginInfo` 记录，通常包含：

- 插件实例 ID
- 插件类型
- 插件配置 JSON

### 10.5.2 `PluginBase<T>`

页面区块插件通常继承 `PluginBase<T>`，从而获得：

- 当前 `AutoPage`
- 当前 `PluginPage`
- 插件参数反序列化
- 配置保存能力
- 删除动作和拖拽能力

### 10.5.3 `PluginPage`

`PluginPage` 是页面插件容器，负责：

- 加载页面已有区块
- 根据布局规则渲染插件
- 在编辑模式下显示“添加区块”“页面布局”等操作
- 保存插件参数和删除插件实例

---

## 10.6 页面布局能力

页面布局由 `PluginPage` 和 `LayoutInfo` 协同实现。当前支持的典型方式包括：

- 无布局，顺序堆叠
- 列布局
- 自定义布局类名

当页面处于编辑模式时，可直接在页面上切换布局方式，并把结果保存到模块配置中。

这也是 Known 低代码页面区别于普通菜单页的重要能力。

---

## 10.7 插件项目组织方式

一个典型插件项目通常包含以下内容：

```text
Plugins/Known.MyBiz/
├─Entities/
├─Services/
├─Pages/
├─Components/
├─wwwroot/
└─AppModule.cs
```

其中：

- `Entities` 存放实体
- `Services` 存放服务接口、客户端、服务端实现
- `Pages` 存放页面
- `Components` 存放页面区块、表单组件、自定义字段
- `wwwroot` 存放插件自己的 CSS、JS、图片等资源

---

## 10.8 已有插件项目说明

当前仓库中的几个插件项目各有职责：

| 插件 | 作用 |
|------|------|
| `Known.Core` | Web 后端增强、动态 API、认证、通知、Redis、进程执行 |
| `Known.Admin` | 开发中心、模块管理、设计器能力 |
| `Known.Cells` | Excel 和 PDF 输出实现 |
| `Known.Sample` | 示例业务模块、报表、大屏、工作流、打印、导入导出样例 |

其中 `Known.Admin` 和 `Known.Sample` 对阅读框架能力尤其重要。

---

## 10.9 业务插件装配方式

业务插件通常提供一个扩展方法，例如：

```csharp
public static class AppModule
{
    public static void AddSample(this IServiceCollection services)
    {
        Config.AddModule(typeof(AppModule).Assembly);
    }
}
```

然后在宿主中调用它：

```csharp
services.AddKnown(...);
services.AddSample();
services.AddKnownWeb(...);
```

插件装配顺序一般建议是：

1. 先 `AddKnown`
2. 再注册业务插件
3. 再注册 Web/Client/Desktop 宿主能力

---

## 10.10 顶部导航插件

`PluginConfig` 会把导航插件和顶部组件插件分开管理。系统默认已支持语言、主题、字号等导航扩展，还会根据 `Config.App.IsSize`、`IsLanguage`、`IsTheme` 等开关控制是否显示。

这说明顶部导航也不是写死的，而是受插件系统驱动。

---

## 10.11 插件体系与低代码的关系

插件体系并不等于低代码，但低代码高度依赖插件体系：

- 模块配置负责定义页面
- 插件页面负责承载页面区块
- 页面区块插件负责组合具体内容
- 开发中心负责设计和保存配置

因此，Known 的低代码能力是建立在插件运行时之上的。

## 本章小结

插件体系的关键结论有四个：

1. Known 的插件是分类明确的运行时能力，不只是 DLL 扫描。
2. 开发中心、导航和页面区块都属于插件体系的一部分。
3. `PluginConfig`、`PluginPage`、`PluginBase<T>` 是运行时核心。
4. 低代码页面、页面布局和可视化装配都建立在这套机制之上。
