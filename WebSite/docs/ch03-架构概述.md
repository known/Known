# 第3章 架构概述

Known 的架构并不是传统意义上的“前端一个仓库、后端一个仓库、脚手架再来一套配置中心”。它更接近“统一核心库 + 多宿主 + 多插件”的平台架构。

---

## 3.1 总体结构

从仓库结构看，Known 可以抽象为下图：

```text
宿主层
├─Known.Server
├─Known.Wasm
├─Known.WasmHost
├─Known.WinForm
└─Known.Maui

插件层
├─Known.Core
├─Known.Admin
├─Known.Cells
├─Known.Sample
└─自定义业务插件

核心层
└─Known
   ├─配置与装配
   ├─实体模型
   ├─数据访问
   ├─服务模型
   ├─页面与组件
   ├─权限菜单
   ├─工作流
   ├─AI
   ├─微信
   └─插件运行时
```

宿主负责启动和运行环境，插件负责功能扩展，核心层负责统一规则和基础设施。

---

## 3.2 启动装配架构

Known 的装配入口主要集中在两个位置：

- `Known/Extension.cs`
- `Plugins/Known.Core/CoreExtension.cs`

### 3.2.1 `AddKnown`

`AddKnown` 负责注入前端和通用运行时能力，例如：

- `Context`
- `UIContext`
- `JSService`
- `UIService`
- `IAuthStateProvider`
- `IPluginService`
- `IExtendService`
- 样式和脚本资源
- `UIConfig` 的默认设置

### 3.2.2 `AddKnownCore`

`AddKnownCore` 负责注入后端运行所需能力，例如：

- `IEntityService<>`
- `ImportContext`
- `IUserHandler`
- 数据访问初始化
- 日志初始化
- 微信 API 初始化
- 服务端类扫描与注入

### 3.2.3 `AddKnownWeb`

这个扩展来自 `Known.Core` 插件，补齐 ASP.NET Core Web 能力：

- MVC Controllers
- 动态 WebApi
- SignalR 通知
- Razor Pages
- 认证状态提供器
- 静态文件与上传文件映射

### 3.2.4 `UseKnown`

`UseKnown` 负责真正激活运行时：

- 配置静态文件
- 配置 `/Files` 与 `/UploadFiles`
- 开启路由、防伪、控制器、Razor Pages、SignalR Hub
- 初始化数据库表、语言和模块数据

---

## 3.3 分层说明

### 3.3.1 领域模型层

以 `EntityBase` 和系统实体为核心，负责数据结构、验证、审计字段和 UI 元数据承载。

### 3.3.2 数据访问层

以 `Database`、`QueryBuilder<T>`、`DbProvider` 为核心，负责多数据库统一访问。

### 3.3.3 服务层

以 `IService`、`ServiceBase`、`ClientBase` 为核心，负责业务逻辑与双端通信。

### 3.3.4 页面层

以 `BasePage`、`BaseTablePage<T>`、`BaseForm<T>`、`BaseTabPage` 为核心，负责页面开发和 UI 组织。

### 3.3.5 平台能力层

以权限、多语言、工作流、AI、微信、任务、导入导出、插件为核心，构成平台能力面。

---

## 3.4 程序集扫描与元数据注册

Known 的很多能力依赖程序集扫描。核心入口是：

```csharp
Config.AddModule(assembly);
```

该方法会把程序集交给初始化器解析，自动收集：

- 路由页面
- 菜单信息
- 按钮动作
- 语言默认项
- 导入器
- 任务处理器
- 工作流类
- 自定义字段组件
- WebApi 服务
- 插件定义

这也是 Known 业务插件为什么必须显式调用 `Config.AddModule` 的根本原因。

---

## 3.5 菜单、路由与权限的关系

Known 不是把菜单、路由和权限分成三套孤立配置，而是让它们通过特性和系统表统一协作。

典型关系如下：

1. 页面类声明 `[Route]`，确定访问地址。
2. 页面类声明 `[Menu]` 或 `[DevPlugin]`，确定导航入口。
3. 角色模块表 `SysRoleModule` 负责授权。
4. `UIConfig.IgnoreRoutes` 控制某些路由是否跳过鉴权。
5. `CoreConfig.IsRoleRoute` 控制角色管理中是否显示路由授权。

这使“页面入口”和“安全边界”天然绑定。

---

## 3.6 配置模型

Known 的配置体系分成三层：

| 类型 | 代表类 | 作用 |
|------|--------|------|
| 应用配置 | `Config` | 全局状态、程序集、模块、运行模式、上传路径 |
| 后端配置 | `CoreConfig` | 安装、注册、登录、权限、工作流、任务、扩展钩子 |
| UI 配置 | `UIConfig` | 页面布局、系统页签、用户页签、模块页签、错误页 |

这种拆分让宿主层、平台层和 UI 层拥有不同的扩展入口。

---

## 3.7 多端架构差异

### 3.7.1 Server

- 页面和服务端在同一 ASP.NET Core 进程内运行
- 可直接使用 `ServiceBase` 和数据库
- 适合后台管理系统

### 3.7.2 Wasm

- UI 在浏览器中运行
- 通过 `ClientBase` 调用后端 `[WebApi]` 服务
- 需要 `Known.Wasm` + `Known.WasmHost` 配合

### 3.7.3 Desktop

- WinForm 和 MAUI 通过 `AddKnownDesktop` 进入桌面模式
- 默认关闭通知 Hub
- 常与本地 SQLite 配合

这种设计保证了框架核心不变，只切换宿主装配方式。

---

## 3.8 插件架构

Known 的插件不是简单的 DLL 扫描，而是有明确分类：

- 普通插件：`[Plugin]`
- 开发中心插件：`[DevPlugin]`
- 顶部导航插件：`[NavPlugin]`
- 页面区块插件：`[PagePlugin]`

运行时由 `PluginConfig` 分类管理，页面区块由 `PluginPage` 承载，开发中心插件通过 `/dev/*` 路由呈现。

---

## 3.9 低代码架构

Known 的低代码主线主要围绕这些对象展开：

- `SysModule` 或增强模块实体
- `AutoPage`
- `AutoService`
- `PluginPage`
- `LayoutInfo`
- `PluginInfo`

一个模块记录不仅代表菜单项，也可能代表一个自动页面、一个插件页面或一个 IFrame 页面。运行时会根据模块的 `Target` 和配置数据决定如何渲染。

## 本章小结

Known 的架构关键点可以归纳为：

1. 核心库负责规则，宿主负责运行，插件负责扩展。
2. 装配通过 `AddKnown`、`AddKnownCore`、`AddKnownWeb`、`UseKnown` 完成。
3. 系统能力高度依赖程序集扫描和特性驱动。
4. 多端只是宿主差异，不是业务模型差异。
