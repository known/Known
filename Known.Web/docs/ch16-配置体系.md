# 第16章 配置体系

Known 的配置体系分为应用配置、后端配置和 UI 配置三层，分别由 `Config`、`CoreConfig` 和 `UIConfig` 主导。理解这三层，是掌握二次开发能力的关键。

---

## 16.1 `Config`

`Config` 是最顶层的全局配置中心，负责：

- 应用信息 `App`
- 程序集列表 `Assemblies`
- 初始模块 `Modules`
- 动作集合 `Actions`
- 字段组件类型 `FieldTypes`
- 运行模式 `RenderMode`
- 上传路径和静态文件路径
- 应用级回调 `OnInitial`、`OnAdmin`

它更偏“系统全局状态与装配入口”。

---

## 16.2 `CoreConfig`

`CoreConfig` 负责服务端和平台级扩展点，常见内容包括：

- `IsRoleRoute`
- `UserSetting`
- `OnInitial`
- `OnAdmin`
- `OnInstall`
- `OnInstallModules`
- `OnNewUser`
- `OnRegistering`
- `OnRegistered`
- `OnLoging`
- `OnLoged`
- `OnDatabase`
- `CheckSystem`

这些钩子使你可以在不改核心源码的前提下接管安装、登录、注册、租户数据库选择等关键逻辑。

---

## 16.3 `UIConfig`

`UIConfig` 负责前端和页面层配置，常见内容包括：

- `SideWidth`
- `EnableEdit`
- `HomeUrl`
- `TopNavType`
- `UserProfileType`
- `ModulePageType`
- `CompanyTabs`
- `ModuleTabs`
- `ModuleFormTabs`
- `UserTabs`
- `UserFormTabs`
- `SystemTabs`
- `IgnoreRoutes`

其中最重要的一点是：很多系统页面并不是写死的，而是由这些标签字典动态扩展。

---

## 16.4 宿主配置入口

在不同宿主中，应用通常会通过 `AddKnown(...)` 或更高层扩展方法为 `AppInfo` 赋值，例如：

- `Id`
- `Name`
- `Assembly`
- `WebRoot`
- `ContentRoot`
- `Database`
- 是否平台模式、是否顶部菜单等开关

这部分决定应用的基本运行形态。

---

## 16.5 推荐配置方式

1. 应用基本信息放在 `Config.App`。
2. 平台逻辑钩子放在 `CoreConfig`。
3. UI 扩展和页签注入放在 `UIConfig`。
4. 业务模块自己的开关和参数放在插件自身配置类中。

---

## 相关源码文件

- `Known/Config.cs`：应用级全局配置。
- `Known/CoreConfig.cs`：后端扩展点。
- `Known/Blazor/UIConfig.cs`：UI 配置。
- `Known.Server/AppConfig.cs`：Server 宿主配置示例。
- `Known.Wasm/AppConfig.cs`：Wasm 宿主配置示例。
