# 第2章 快速开始

本章从源码仓库出发，说明如何把 Known 运行起来，并基于现有结构开始开发。由于 Known 已经提供多个宿主和插件示例，最快的上手方式不是新建空项目，而是先跑通示例系统。

---

## 2.1 环境准备

### 2.1.1 .NET 版本

从仓库项目文件可以看到，Known 及其插件支持 `net8.0`、`net9.0`、`net10.0` 多目标，因此并不是只能使用 .NET 10。

推荐环境：

- .NET SDK 8/9/10 之一
- Visual Studio 2022/2026 或 JetBrains Rider
- Windows 开发环境优先，尤其在 WinForm、MAUI、SQLite、本地文件调试场景下更方便

### 2.1.2 数据库

示例项目默认采用 SQLite，最容易直接跑通。`Known.Server/Program.cs` 与 `Known.WasmHost/Program.cs` 中已展示如何切换为其他数据库。

支持类型包括：

- SQLite
- SQL Server
- MySQL
- PostgreSQL
- Oracle
- 达梦
- Access

### 2.1.3 前端依赖

Known 依赖的前端能力主要通过静态资源方式提供，不需要额外配置 npm 工程。常见资源由 `Known/Extension.cs` 自动注入，例如：

- Ant Design Blazor
- jQuery
- ECharts
- SignalR
- PDFObject
- 条码、二维码、扫码库

## 2.2 仓库结构认识

仓库主结构如下：

```text
Known/
├─Known                框架核心库
├─Plugins              插件项目目录
│ ├─Known.Core         Web 后端增强插件
│ ├─Known.Admin        开发中心/后台增强插件
│ ├─Known.Cells        Excel 实现插件
│ └─Known.Sample       示例业务插件
├─Known.Server         Server 模式宿主
├─Known.Wasm           Wasm 客户端宿主
├─Known.WasmHost       Wasm 后端宿主
├─Known.WinForm        WinForm 宿主
└─Known.Maui           MAUI 宿主
```

如果你的目标是理解框架，优先看 `Known.Server` 和 `Plugins/Known.Sample`。如果你的目标是理解平台能力，再看 `Known.Admin` 和 `Known.Core`。

## 2.3 运行第一个系统

### 2.3.1 运行 Server 示例

最直接的入口是 `Known.Server`。

启动关键代码：

```csharp
builder.Services.AddApplication(option =>
{
    option.App.WebRoot = builder.Environment.WebRootPath;
    option.App.ContentRoot = builder.Environment.ContentRootPath;
    option.App.Assembly = typeof(Program).Assembly;
    option.App.Database = db =>
    {
        db.AddSQLite<Microsoft.Data.Sqlite.SqliteFactory>(connString);
    };
});
```

这个扩展方法内部会继续完成：

1. `services.AddKnown(...)`
2. `services.AddSample()`
3. `services.AddKnownWeb(...)`
4. `services.AddHostedService<TestWorker>()`

也就是说，示例系统不是裸 Blazor 程序，而是已经把框架核心和示例业务插件一起装配好了。

### 2.3.2 请求管线

在 `Known.Server/Program.cs` 中，真正启动系统的是：

```csharp
app.UseHttpsRedirection();
app.UseAntiforgery();
app.UseApplication();
app.MapRazorComponents<App>()
   .AddInteractiveServerRenderMode()
   .AddAdditionalAssemblies([.. Config.Assemblies]);
```

其中 `UseApplication()` 会继续调用 `app.UseKnown()`，加载静态资源、控制器、Razor Pages、SignalR Hub，并在连接数据库时自动执行迁移和初始化。

## 2.4 初次理解启动链路

理解 Known 的最快方式，是把“系统能跑起来”拆成四个步骤：

1. 配置 `AppInfo`：应用 ID、名称、程序集、数据库、路径。
2. 注册框架核心：`AddKnown`、`AddKnownCore` 或 `AddKnownWeb`。
3. 注册业务插件：如 `AddSample()`。
4. 启动运行时：`UseKnown()` 或宿主自定义封装。

对应源码位置：

- 核心装配：`Known/Extension.cs`
- Web 装配：`Plugins/Known.Core/CoreExtension.cs`
- 示例业务：`Plugins/Known.Sample/AppModule.cs`
- 宿主封装：`Known.Server/AppConfig.cs`

---

## 2.5 第一个业务插件应放在哪里

在 Known 中，不推荐把所有代码都堆到宿主项目。更推荐的做法是新建一个插件项目，例如：

```text
Plugins/
└─Known.MyBiz/
   ├─Entities/
   ├─Services/
   ├─Pages/
   ├─Components/
   └─AppModule.cs
```

然后像 `Known.Sample` 一样提供一个扩展方法：

```csharp
public static class AppModule
{
    public static void AddMaterialPlugin(this IServiceCollection services)
    {
        Config.AddModule(typeof(AppModule).Assembly);
    }
}
```

最后在宿主启动时调用它。

## 2.6 创建第一个实体和页面

一个最小业务功能通常由三个部分组成：

1. 实体
2. 服务
3. 页面

### 2.6.1 实体

```csharp
public class TbMaterial : EntityBase
{
    [Required]
    [MaxLength(50)]
    [Column(Width = 150, IsQuery = true, IsViewLink = true)]
    [DisplayName("客户料号")]
    public string CustGNo { get; set; }

    [Column]
    [DisplayName("备注")]
    public string Note { get; set; }
}
```

### 2.6.2 服务

```csharp
public interface IProduceService : IService
{
    Task<PagingResult<TbMaterial>> QueryMaterialsAsync(PagingCriteria criteria);
}

[WebApi, Service]
class ProduceService(Context context) : ServiceBase(context), IProduceService
{
    public Task<PagingResult<TbMaterial>> QueryMaterialsAsync(PagingCriteria criteria)
    {
        return Database.QueryPageAsync<TbMaterial>(criteria);
    }
}
```

### 2.6.3 页面

```csharp
[Route("/pms/materials")]
[Menu(AppConstant.Produce, "客户料号", "bars", 1)]
public class MaterialList : BaseTablePage<TbMaterial>
{
}
```

在 Known 中，这已经足以形成一个可进入菜单的页面骨架。后续只需补充服务调用、表格列、表单弹窗等细节。

## 2.7 快速验证是否装配成功

完成实体、服务和页面后，可按下面方式检查：

1. 页面是否出现在菜单中。
2. 路由是否能直接访问。
3. 开发中心的 WebApi 页面是否能看到服务方法。
4. 数据库中是否已生成或能正确访问对应表。

如果菜单不显示，优先排查：

- 是否调用了 `Config.AddModule(assembly)`
- 页面类是否带 `[Route]` 和 `[Menu]`
- 宿主是否通过 `Config.Assemblies` 将程序集加入运行时

## 2.8 发布与部署

### 2.8.1 Web 部署

Server 和 WasmHost 模式本质都是 ASP.NET Core 应用，部署方式与普通 .NET Web 程序一致。需要重点关注：

- `appsettings.json` 中的连接串
- 静态资源目录
- `UploadFiles` 与 `Files` 目录权限
- 反向代理与 HTTPS 配置

### 2.8.2 桌面部署

WinForm 和 MAUI 模式通常使用本地 SQLite 和本地文件目录，适合单机或轻量分发场景。发布时要确认：

- SQLite 文件路径是否正确
- 资源文件是否一起打包
- 本地上传目录是否可写

---

## 2.9 推荐上手顺序

如果你第一次接触 Known，建议按这个顺序操作：

1. 跑通 `Known.Server`
2. 进入系统后台，认识内置模块和示例业务
3. 阅读 `Known.Sample` 的实体、服务、页面
4. 新建自己的插件项目
5. 增加一个实体和一个列表页
6. 再去看开发中心、工作流、导入导出等高级能力
