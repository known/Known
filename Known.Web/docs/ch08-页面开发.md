# 第8章 页面开发

页面开发是 Known 最直接的使用入口。框架通过一组页面基类，把查询、列表、表单、按钮、标签页、弹窗和权限控制组织成统一开发模型。

---

## 8.1 页面基类体系

Known 的页面基类主要定义在：

- `Known/Blazor/Base.Page.cs`
- `Known/Blazor/Base.TablePage.cs`
- `Known/Blazor/Base.Form.cs`

主要类型如下：

| 基类 | 适用场景 |
|------|----------|
| `BasePage` | 普通页面、仪表盘、详情页、自定义页面 |
| `BaseTablePage<T>` | 列表页、查询页、管理页 |
| `BaseForm<T>` | 编辑页、弹窗表单、明细页 |
| `BaseTabPage` | 标签页组合页面 |
| `BaseStepPage` | 分步骤页面 |

---

## 8.2 `BasePage`

`BasePage` 是所有页面的基础，适合：

- 首页
- 仪表盘
- 开发中心页面
- 报表页
- 自定义交互页面

在 `BasePage` 中，通常会重写：

- `OnInitPageAsync()`：初始化页面数据
- `OnRenderAsync()`：首次渲染后处理
- `BuildPage(RenderTreeBuilder builder)`：构建主要内容

---

## 8.3 `BaseTablePage<T>`

这是后台管理系统中最常用的页面基类。它封装了：

- 查询栏
- 表格
- 工具栏
- 行操作
- 批量操作
- 弹窗/抽屉表单
- 导入导出

典型页面包括：

- `SysUserList`
- `SysRoleList`
- `SysTaskList`
- `TenantPage`
- `Known.Sample` 中的大量业务列表页

### 8.3.1 常见写法

```csharp
public class MaterialList : BaseTablePage<TbMaterial>
{
    private IProduceService Service;

    protected override async Task OnInitPageAsync()
    {
        await base.OnInitPageAsync();
        Service = await CreateServiceAsync<IProduceService>();

        Table.FormType = typeof(MaterialForm);
        Table.Form = new FormInfo { Width = 900 };
        Table.OnQuery = Service.QueryMaterialsAsync;
    }

    [Action]
    public void New() => Table.NewForm(Service.SaveMaterialAsync, new TbMaterial());
}
```

这类页面开发效率很高，因为查询、表格、弹窗和保存流程都已经封装好了。

---

## 8.4 `BaseForm<T>`

`BaseForm<T>` 适合：

- 新增/编辑表单
- 明细查看
- 弹窗内表单
- 抽屉内表单
- 主从表录入页

它通常与 `FormModel<T>` 一起使用，负责：

- 表单字段生成
- 验证显示
- 保存动作
- 底部按钮
- 只读和查看模式切换

---

## 8.5 标签页与组合页面

### 8.5.1 `BaseTabPage`

当一个页面需要由多个子区域组合时，适合使用 `BaseTabPage`。典型例子包括：

- `SysSystem`
- `ModulePage`
- `UserProfile`

这些页面通过 `Tab.AddTab(...)` 动态加入多个页签，并可结合 `UIConfig.SystemTabs`、`UIConfig.ModuleTabs` 等实现可扩展标签页。

### 8.5.2 `BaseStepPage`

适合流程化录入、向导式操作或多步骤配置页面。

---

## 8.6 菜单和路由声明

页面要成为系统可访问入口，通常要声明两个特性：

```csharp
[Route("/pms/materials")]
[Menu(AppConstant.Produce, "客户料号", "bars", 1)]
public class MaterialList : BaseTablePage<TbMaterial>
{
}
```

其中：

- `[Route]` 决定地址
- `[Menu]` 决定菜单挂载位置和显示信息

开发中心页面则通常使用 `[DevPlugin]`，例如：

```csharp
[Route("/dev/coding")]
[DevPlugin("代码生成", "code", Sort = 98)]
public class CodingPage : BasePage
{
}
```

## 8.7 按钮动作声明

Known 使用 `[Action]` 定义工具栏按钮和行按钮，这也是按钮权限控制的基础。

示例：

```csharp
[Action]
public void New() => Table.NewForm(Service.SaveMaterialAsync, new TbMaterial());

[Action]
public void Delete(TbMaterial row) => Table.Delete(Service.DeleteMaterialsAsync, row);
```

`ActionAttribute` 可配置：

- `Icon`
- `Name`
- `Title`
- `Style`
- `Visible`
- `Group`
- `Tabs`

这些动作信息会被系统扫描并进入权限模型。

## 8.8 列表页开发要点

### 8.8.1 查询数据来源

推荐通过服务层返回 `PagingResult<T>`，让页面只做绑定，不做复杂查询逻辑。

### 8.8.2 表格列来源

列表列可以来自两种方式：

1. 实体上的 `[Column]` 元数据
2. 页面中手工追加 `Table.AddColumn(...)`

一般建议：

- 通用字段写在实体上
- 页面特殊列写在页面里

### 8.8.3 表单弹出方式

常见形式包括：

- 弹窗表单
- 抽屉表单
- 独立页面表单

`Table.FormType`、`Table.Form` 等属性可控制显示方式。

---

## 8.9 低代码页面与编码页面

Known 同时支持两种页面开发方式：

### 8.9.1 编码式页面

直接继承基类写 C# 页面，适合复杂业务、长期维护和深度定制。

### 8.9.2 低代码页面

通过 `AutoPage`、模块配置、设计器和插件区块形成页面，适合快速交付和平台化场景。

二者不是替代关系，而是可混合使用：

- 复杂核心页面用编码式
- 管理维护页面用低代码

---

## 8.10 页面开发常见组件

框架中还提供了一组高频组件用于页面搭建，例如：

- `KTable`
- `KToolbar`
- `KAction`
- `KUpload`
- `KCodeView`
- `KFileView`
- `KListBox`
- `TabPage`
- `StepForm`
- 二维码、条码、扫描、PDF、图表等组件

因此，页面开发不是只靠基类，还可以结合这些组件快速完成复杂界面。

---

## 8.11 页面开发建议

1. 管理列表优先使用 `BaseTablePage<T>`。
2. 自定义布局页面优先使用 `BasePage`。
3. 系统设置类页面优先使用 `BaseTabPage`。
4. 动作统一使用 `[Action]`，便于权限控制。
5. 查询与保存逻辑放在服务层，页面只组织交互。

## 本章小结

Known 的页面开发模型可以概括为：

1. 基类负责页面骨架。
2. 特性负责菜单、按钮和元数据。
3. 服务负责业务和数据。
4. 组件负责复杂交互和细节表现。
