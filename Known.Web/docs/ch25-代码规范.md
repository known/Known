# 第25章 代码规范

Known 的代码规范重点不只是命名风格，更包括与框架约定保持一致。因为很多能力依赖程序集扫描、特性和统一基类，一旦随意偏离约定，就会直接影响装配和运行结果。

---

## 25.1 项目组织规范

推荐按插件项目组织业务代码：

```text
Plugins/Known.MyBiz/
├─Entities/
├─Services/
├─Pages/
├─Components/
└─AppModule.cs
```

不要把大量业务代码直接堆在宿主项目中。

---

## 25.2 命名建议

- 实体：`TbMaterial`、`SysUser`
- 服务接口：`IProduceService`
- 服务端实现：`ProduceService`
- 客户端实现：`ProduceClient`
- 列表页：`MaterialList`、`SysUserList`
- 表单页：`MaterialForm`
- 模块入口：`AppModule`

这一命名风格在框架内置代码和示例插件中都很一致。

---

## 25.3 特性使用规范

常见页面应至少具备：

- `[Route]`
- `[Menu]` 或 `[DevPlugin]`

常见服务应至少具备：

- `[Service]`
- 需要远程调用时再加 `[WebApi]`

常见实体应优先具备：

- `[Table]`
- 合理的 `[Column]` 与 `[Form]`

---

## 25.4 分层职责规范

1. 页面负责交互和显示。
2. 服务负责业务逻辑和事务。
3. 实体负责模型和元数据。
4. 导入、任务、工作流回调分别放在各自扩展点中。

不要在页面中塞入大量业务 SQL 或复杂流程判断。
