# 第28章 从 0 到 1 开发一个插件模块

本章给出一条最贴近当前仓库的实战路径：参考 `Known.Sample`，从零搭一个最小可运行的业务插件模块。目标不是做复杂业务，而是把 Known 的标准开发链路完整走一遍。

---

## 28.1 目标

本章要完成一个最小模块，包含四部分：

1. 一个插件项目入口。
2. 一个实体。
3. 一个服务接口与实现。
4. 一个列表页面。

你完成后，应该能做到：

- 宿主启动时自动扫描模块。
- 菜单中看到页面入口。
- 页面能查询和保存数据。
- 在开发中心的 WebApi 页面中看到对应服务方法。

---

## 28.2 第一步：建立插件项目结构

建议结构：

```text
Plugins/Known.MyModule/
├─Entities/
├─Services/
├─Pages/
├─Components/
└─AppModule.cs
```

最开始不必一次把所有目录都填满，但建议先把结构搭好，后续扩展不会混乱。

---

## 28.3 第二步：编写模块入口

模块入口的职责只有一个：把程序集交给框架扫描。

```csharp
namespace Known.MyModule;

public static class AppModule
{
    public static void AddMyModule(this IServiceCollection services)
    {
        Config.AddModule(typeof(AppModule).Assembly);
    }
}
```

如果你的插件还有静态资源，也可以像 `Known.Sample` 一样在这里统一注册 CSS、JS 和自定义 UI 配置。

---

## 28.4 第三步：定义实体

推荐先做一个最小实体，例如客户料号或仓位这类标准主数据。

```csharp
namespace Known.MyModule.Entities;

public class TbDemoItem : EntityBase
{
    [Required]
    [MaxLength(50)]
    [Column(Width = 150, IsQuery = true, IsViewLink = true)]
    [DisplayName("项目编码")]
    public string Code { get; set; }

    [Column(Width = 180, IsQuery = true)]
    [DisplayName("项目名称")]
    public string Name { get; set; }

    [Column]
    [DisplayName("备注")]
    public string Note { get; set; }
}
```

这里延续的是 `TbMaterial` 的定义方式：

- 继承 `EntityBase`
- 用 `[Column]` 配列表元数据
- 用验证特性保证保存前校验

## 28.5 第四步：定义服务接口与实现

Known 推荐三段式服务开发。最小可运行版本如下：

```csharp
namespace Known.MyModule.Services;

public interface IDemoItemService : IService
{
    Task<PagingResult<TbDemoItem>> QueryItemsAsync(PagingCriteria criteria);
    Task<Result> SaveItemAsync(TbDemoItem info);
    Task<Result> DeleteItemsAsync(List<TbDemoItem> infos);
}

[Client]
class DemoItemClient(HttpClient http) : ClientBase(http), IDemoItemService
{
    public Task<PagingResult<TbDemoItem>> QueryItemsAsync(PagingCriteria criteria)
        => Http.QueryAsync<TbDemoItem>("/DemoItem/QueryItems", criteria);

    public Task<Result> SaveItemAsync(TbDemoItem info)
        => Http.PostAsync("/DemoItem/SaveItem", info);

    public Task<Result> DeleteItemsAsync(List<TbDemoItem> infos)
        => Http.PostAsync("/DemoItem/DeleteItems", infos);
}

[WebApi, Service]
class DemoItemService(Context context) : ServiceBase(context), IDemoItemService
{
    public Task<PagingResult<TbDemoItem>> QueryItemsAsync(PagingCriteria criteria)
        => Database.QueryPageAsync<TbDemoItem>(criteria);

    public async Task<Result> SaveItemAsync(TbDemoItem info)
    {
        var database = Database;
        var model = await database.QueryByIdAsync<TbDemoItem>(info.Id);
        model ??= new TbDemoItem();
        model.FillModel(info);

        var vr = model.Validate(Context);
        if (!vr.IsValid)
            return vr;

        return await database.TransactionAsync(Language.Save, async db =>
        {
            await db.SaveAsync(model);
            info.Id = model.Id;
        }, info);
    }

    public async Task<Result> DeleteItemsAsync(List<TbDemoItem> infos)
    {
        if (infos == null || infos.Count == 0)
            return Result.Error(Language.SelectOneAtLeast);

        return await Database.TransactionAsync(Language.Delete, async db =>
        {
            foreach (var item in infos)
                await db.DeleteAsync<TbDemoItem>(item.Id);
        });
    }
}
```

这个结构已经能同时适配：

- Server 模式本地服务调用
- Wasm 模式远程 HTTP 调用
- 开发中心 WebApi 自动发现

## 28.6 第五步：定义列表页面

列表页最适合直接继承 `BaseTablePage<T>`。

```csharp
namespace Known.MyModule.Pages;

[Route("/demo/items")]
[Menu("TopDemo", "示例项目", "bars", 10)]
public class DemoItemList : BaseTablePage<TbDemoItem>
{
    private IDemoItemService Service;

    protected override async Task OnInitPageAsync()
    {
        await base.OnInitPageAsync();
        Service = await CreateServiceAsync<IDemoItemService>();

        Table.OnQuery = Service.QueryItemsAsync;
    }

    [Action]
    public void New() => Table.NewForm(Service.SaveItemAsync, new TbDemoItem());

    [Action]
    public void Edit(TbDemoItem row) => Table.EditForm(Service.SaveItemAsync, row);

    [Action]
    public void Delete(TbDemoItem row) => Table.Delete(Service.DeleteItemsAsync, row);
}
```

如果你暂时还没写表单组件，也可以先用框架默认表单流程把页面跑起来，再逐步补定制表单。

## 28.7 第六步：在宿主中注册插件

以 `Known.Server` 为例，在宿主装配中引入你的插件：

```csharp
services.AddKnown(info =>
{
    info.Id = AppId;
    info.Name = AppName;
    info.Assembly = typeof(Program).Assembly;
});

services.AddMyModule();
services.AddKnownWeb(action);
```

如果是 Wasm 模式，则在 `Known.Wasm/AppConfig.cs` 或等价宿主装配入口里同样调用 `AddMyModule()`。

---

## 28.8 第七步：验证模块是否成功接入

完成后按下面顺序验证：

1. 启动宿主。
2. 检查菜单中是否出现“示例项目”。
3. 点击页面是否能进入 `/demo/items`。
4. 新增、编辑、删除是否可执行。
5. 进入 `/dev/webapi` 看是否出现 `DemoItemService` 方法。

如果没有成功，优先排查：

- 是否调用了 `Config.AddModule(typeof(AppModule).Assembly)`
- 页面是否有 `[Route]` 和 `[Menu]`
- 服务是否有 `[WebApi, Service]`
- 客户端是否有 `[Client]`

---

## 28.9 第八步：逐步增强模块

当最小模块跑通后，可以继续往里加：

1. 表单页面：自定义 `BaseForm<T>` 表单。
2. 导入能力：新增 `ImportBase<T>` 导入器。
3. 任务能力：把批处理放到 `TaskBase`。
4. 流程能力：为单据增加 `FlowBase` 回调。
5. 页面区块：用 `PagePlugin` 进入低代码页面体系。
6. 多语言：补语言项。

推荐顺序是先把标准 CRUD 做稳定，再叠加平台能力。

public static class AppModule
{

### 28.10.6 `Services/DemoItemService.cs`

```csharp
namespace Known.MyModule.Services;

public interface IDemoItemService : IService
{
    Task<PagingResult<TbDemoItem>> QueryItemsAsync(PagingCriteria criteria);
    Task<TbDemoItem> GetItemAsync(string id);
    Task<Result> SaveItemAsync(TbDemoItem info);
    Task<Result> DeleteItemsAsync(List<TbDemoItem> infos);
}

[Client]
class DemoItemClient(HttpClient http) : ClientBase(http), IDemoItemService
{
    public Task<PagingResult<TbDemoItem>> QueryItemsAsync(PagingCriteria criteria)
        => Http.QueryAsync<TbDemoItem>("/DemoItem/QueryItems", criteria);

    public Task<TbDemoItem> GetItemAsync(string id)
        => Http.GetAsync<TbDemoItem>($"/DemoItem/GetItem?id={id}");

    public Task<Result> SaveItemAsync(TbDemoItem info)
        => Http.PostAsync("/DemoItem/SaveItem", info);

    public Task<Result> DeleteItemsAsync(List<TbDemoItem> infos)
        => Http.PostAsync("/DemoItem/DeleteItems", infos);
}

[WebApi, Service]
class DemoItemService(Context context) : ServiceBase(context), IDemoItemService
{
    public Task<PagingResult<TbDemoItem>> QueryItemsAsync(PagingCriteria criteria)
        => Database.QueryPageAsync<TbDemoItem>(criteria);

    public async Task<TbDemoItem> GetItemAsync(string id)
    {
        var info = await Database.QueryByIdAsync<TbDemoItem>(id);
        info ??= new TbDemoItem();
        return info;
    }

    public async Task<Result> SaveItemAsync(TbDemoItem info)
    {
        var database = Database;
        var model = await database.QueryByIdAsync<TbDemoItem>(info.Id);
        model ??= new TbDemoItem();
        model.FillModel(info);

        var vr = model.Validate(Context);
        if (!vr.IsValid)
            return vr;

        var exists = await database.ExistsAsync<TbDemoItem>(d => d.Id != model.Id && d.Code == model.Code);
        if (exists)
            return Result.Error($"项目编码[{model.Code}]已存在！");

        return await database.TransactionAsync(Language.Save, async db =>
        {
            await db.SaveAsync(model);
            info.Id = model.Id;
        }, info);
    }

    public async Task<Result> DeleteItemsAsync(List<TbDemoItem> infos)
    {
        if (infos == null || infos.Count == 0)
            return Result.Error(Language.SelectOneAtLeast);

        return await Database.TransactionAsync(Language.Delete, async db =>
        {
            foreach (var item in infos)
                await db.DeleteAsync<TbDemoItem>(item.Id);
        });
    }
}
```

## 28.11 宿主接入样板

### 28.11.1 Server 宿主接入

在 `Known.Server/AppConfig.cs` 风格的宿主中，可按下面方式接入：

```csharp
internal static void AddApplication(this IServiceCollection services, Action<CoreOption> action)
{
    services.AddKnown(info =>
    {
        info.Id = AppId;
        info.Name = AppName;
        info.Assembly = typeof(Program).Assembly;
    });

    services.AddMyModule();
    services.AddKnownWeb(action);
}
```

### 28.11.2 Wasm 宿主接入

在 `Known.Wasm/AppConfig.cs` 风格的宿主中：

```csharp
public static void AddApplication(this IServiceCollection services)
{
    services.AddKnown(info =>
    {
        info.Id = AppId;
        info.Name = AppName;
    });

    services.AddMyModule();
}
```

随后由 `AddApplicationClient(...)` 调用 `AddKnownClient(...)` 即可。

## 28.12 开发完成后的检查清单

建议在每次新增模块后检查：

1. 插件项目是否已被宿主引用。
2. `AppModule` 是否已执行 `Config.AddModule(...)`。
3. 页面是否有 `[Route]` 和 `[Menu]`。
4. 服务是否有 `[WebApi, Service]`。
5. 客户端是否有 `[Client]`。
6. 菜单是否已出现在系统中。
7. `/dev/webapi` 是否能看到服务。
8. 列表页查询和保存是否正常。

## 本章小结

从 0 到 1 开发一个 Known 插件模块，最关键的不是页面长什么样，而是先把标准链路搭起来：

1. 插件入口负责程序集扫描。
2. 实体负责数据和元数据。
3. 服务负责查询、保存和删除。
4. 页面负责菜单入口和交互。
5. 宿主负责装配和运行。
